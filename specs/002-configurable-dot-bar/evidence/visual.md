# Bar visual evidence

`BarVisual::test_feather` produces 16 software-rendered PNGs under `dist/visual/bar-*.png`: four edges across white, dark, colorful and busy synthetic wallpapers. The captures use `tests/visual/Fixture.qml` and contain no private wallpaper. The current captures show a continuous dark edge core and a transparent fade before the visual boundary. Three `bar-breathe-{0,1,2}.png` frames on white show the distributed field changing over 2.4 seconds; the test compares their pixels so a stationary field fails. Auto-hide and reduced-motion behavior still need live visual review.

After the next correction, `bar-hover.png` and `bar-reduced.png` capture the bounded local light on a synthetic bright fixture. The field uses broader Gaussian shoulders, and `BarLattice` tests verify workspace node positions on all four edges and omission of the underlying decorative node. `BarMotion` tests verify pointer following, bounded departure and stationary reduced-motion behavior. These tests do not establish that the live Niri pointer trajectory or workspace activation looks right to the user.

The latest live eDP-1 top-edge crop was reviewed locally on 2026-11-24 without copying the private screen into the repository. User review of the two traveling fronts exposed a straight cutoff where the field met the visual window boundary. The current version removes fixed module lobes and uses four continuously breathing, drifting patches in distributed regions. `bar-ambient-patch.png` is a synthetic white-background capture showing a feathered patch with no rectangular edge; pixel tests verify that its inner boundary is nearly white on all four edges. Static and pointer fields also fade to zero before the clip boundary. Final live visual review remains open.

On 2026-11-25 the user accepted the continuous bar and requested a slight extension under each module. `bar-module-accent.png` renders short and long accents on white; the visual test checks that both are local, that a stronger pulse darkens the accent, and that the field is transparent at the window boundary. A separate layout test changes widget widths/count and verifies the accent regions follow the new bounds. A temporary live top-edge crop was inspected locally and was not committed because it contains private screen content.

An attempted 90-pixel visual window was reverted after the user clarified that the **application** should be higher. The accepted bar window is again 78 pixels deep by default, and the four-edge synthetic captures use that depth. Compositor reservation was reduced from 36 to 24 pixels while controls/input remain at 36. A temporary live eDP-1 crop showed the open application's top border rising from roughly y=63 to y=48; the bar field still fades smoothly over its upper area. The crop remains outside the repository because it contains private screen content.

After the lattice alignment adjustment, a local HDMI-A-1 top-edge crop showed the first actionable workspace dot at the second lattice column and the enlarged clock centered on the second dot row, with no decorative dots crossing its digits. User review exposed gaps where decorative dots had been suppressed under other widgets. That suppression now applies only around the clock. A later eDP-1 crop showed a separate leading dot, the actionable workspace dots, and Niri's empty trailing workspace as a smaller regular background dot. The crops remain in `/tmp` because they include private window content. Left, right and bottom geometry is covered by `BarLattice`; their live appearance remains to be reviewed.

The leading dot was then corrected to use the same background lattice rendering as the trailing dot. A later local eDP-1 crop showed both side dots small and faint, with the larger actionable workspace indicators between them.

The next user screenshot showed that those side dots were actually missing in some live layouts. Runtime logging traced this to the clock's exclusion rectangle being mapped before the clock group centered and remaining over the workspace region. The exclusion now updates with group placement. A magnified local eDP-1 crop after the fix shows both ordinary dots present immediately beside the workspace indicators; no separate dot overlay or row-wide brightness change remains.

The clock's accent uses the same layout-position tracking. A local eDP-1 crop after a one-step length and half-step depth increase showed a soft dark extension centered beneath the time. The updated synthetic `bar-module-accent.png` includes the clock variant and passed its locality, breathing and boundary checks. The live crop remains in `/tmp` because it contains private screen content.

The faster ambient version was captured twice on eDP-1 with about three seconds between frames. Comparing RGB red values over y=43–76 yielded mean absolute changes of 14.35, 12.93, 13.23 and 15.01 across the four 400-pixel horizontal quarters. This confirms distributed visible change during the sample. Both crops remain in `/tmp` because they include private window content; the software-rendered boundary tests still pass.
