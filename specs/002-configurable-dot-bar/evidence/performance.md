# Performance evidence

The bar uses event-driven Niri, UPower, PipeWire, system-tray and minute-clock updates. The static field originally repainted repeatedly because unrelated Niri events replaced the workspace object; after keeping a stable workspace snapshot and comparing node signatures, temporary paint counters showed zero static-field paints per second at rest. The live shell fell from about 40% of one core to 0–5% in that isolation run. An initial per-frame ambient wave raised the live two-output shell to 34.9%, 39.0% and 35.5% CPU in consecutive `top` samples; it was replaced with local updates. The rejected two-sided moving fronts measured 14.9%, 13.5% and 10.5%. The continuous four-patch version updates local geometry every 160 ms. On 2026-11-25, source shell PID 857 measured 5.0%, 8.0% and 7.5% CPU before the per-module accents, then 5.0%, 8.0% and 7.5% after them, across two-second `top` samples; resident memory stayed about 317–318 MiB. The accents change opacity over cached fields and did not increase sustained CPU in this short observation. This is a full-shell live observation, not a fresh-process bar-only comparison; frame pacing and hidden-mode measurements remain open.

After speeding the four ambient patches to 3.3–5.8-second cycles, the running two-output source shell measured 10%, 9% and 8% of one CPU core in consecutive two-second `top` samples. The 160 ms update interval stayed unchanged. This is a short full-shell observation under a different desktop workload, not a controlled before/after comparison; settled bar-only, hidden-mode and frame-pacing measurements remain open.
